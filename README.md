# Events API

REST API для управления мероприятиями на ASP.NET Core Web API (.NET 10).
Данные хранятся в памяти приложения. Для ручной проверки доступен Swagger UI.

## Требования

- .NET SDK 10

## Запуск

- Скачать проект из репозитория или склонируйте его
- Запустить командную строку
- Выполнить команду cd <папка> для перехода в папку проекта
- Выполнить команду dotnet restore
- Выполнить команду dotnet build
- Выполнить команду dotnet run --project src/EventsApi
- Откройте в браузере: http://localhost:5004/swagger/index.html

## API

| Метод | Путь | Описание | Ответы |
|-------|------|----------|--------|
| GET | `/events` | Список событий с фильтрацией и пагинацией | 200, 400 |
| GET | `/events/{id}` | Событие по id | 200, 404 |
| POST | `/events` | Создать событие | 201, 400 |
| PUT | `/events/{id}` | Обновить событие | 200, 400, 404 |
| DELETE | `/events/{id}` | Удалить событие | 200, 404 |

`id` в теле запроса для `POST` и `PUT` игнорируется — идентификатор назначает сервер при создании и берёт из URL при обновлении.

### Параметры GET /events

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|:---:|----------|
| `title` | string | — | Поиск по названию (регистронезависимый, частичное совпадение) |
| `from` | DateTime | — | События, начинающиеся не раньше указанной даты |
| `to` | DateTime | — | События, заканчивающиеся не позже указанной даты |
| `page` | int | 1 | Номер страницы |
| `pageSize` | int | 10 | Количество элементов на странице |

Все фильтры работают совместно (логическое И). Ответ — `PaginatedResult`:

```json
{
  "totalCount": 42,
  "items": [ { "id": 1, "title": "...", "startAt": "...", "endAt": "..." } ],
  "page": 1,
  "pageSize": 10
}
```

`page` и `pageSize` должны быть >= 1, иначе `400 Bad Request`.

## Валидация

- `title` — обязательное, не пустое и не из одних пробелов, до 30 символов;
- `startAt`, `endAt` — обязательные;
- `endAt` должен быть позже `startAt`.

При нарушении — `400 Bad Request` с деталями.

## Формат ошибок

Все необработанные исключения перехватываются middleware и возвращаются в формате `ProblemDetails` (`application/problem+json`):

```json
{
  "status": 400,
  "detail": "EndAt must be later than StartAt."
}
```

| Исключение | HTTP-статус |
|-----------|:---:|
| `ArgumentException` | `400 Bad Request` |
| Остальное | `500 Internal Server Error` |

`404 Not Found` для несуществующих событий возвращается контроллером.
